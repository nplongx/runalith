# Workstream 6 — Governance Authority

**Deployable:** Governance & Interface. **Status:** proposed boundary; owner unassigned. See the [master eight-part plan](../EIGHT_PART_PARALLEL_PLAN.md).

## Mandate

Own trust and authorization truth. Verify who is trusted, what policy applies and whether an exact subject/action is approved; issue independently verifiable receipts.

## Ownership

- Trust roots, domain/key separation, administrator provisioning and high-water state.
- Key rotation/revocation/anti-rollback, reviewer identities, maker/checker/quorum and reviewer attestations.
- Global approval/security policy versions and decision evaluation.
- Nonce consumption, replay resistance, signing-key custody, decision receipts and receipt verification.
- Trusted-skill authority consumed by workstream 1.

## Explicit non-ownership

No workflow/task/lease state; no worker/process/provider truth; no AGG graph/candidate/checkpoint ledger; no northbound MCP business rules; no workflow-local success predicates.

## Current code map

`runalith-trust`; Governance contracts in `runalith-protocol`; trust/reviewer/decision code currently embedded in `runalith-store`; `docs/rust-part3-governance-interface-contracts.md`. `StoreGovernanceDecisionBackend` is a single-file D-01 compatibility adapter, not a separately owned Governance DB/backend.

## Public outputs

`ApprovalRequestV1`, `ApprovalDecisionReceiptV1`, `TrustSnapshotRefV1`, `ReviewerAttestationV1`, `TrustedSkillResolutionV1`, `NonceConsumptionReceiptV1` and signer/verifier key-version policy. Receipts bind exact workflow candidate, plan digest, action scope, reviewer set, policy version and request digest.

**Consumes:** exact candidate/plan/action references from workstreams 1–2; source-evidence manifest reference from workstream 7; authenticated Control caller identity.

## Policy boundary

This workstream owns global trust/reviewer/approval/security policy. Workstreams 1–2 own workflow-local policy packs, success predicates and immutable enforcement snapshots. Workflow-local policy may reference a Governance policy version/digest but cannot redefine trust roots, reviewer quorum or approval authority. This proposed boundary requires contract-owner ratification before data ownership changes.

## Parallel development

Pure signature/canonicalization vectors; trust lifecycle state validators; quorum algorithms; receipt schema/verifier tests; fake backend and test-key-only signing. Do not provision production keys, roots or reviewer identity as part of parallel implementation.

## Acceptance

1. Exact subject/audience/action/plan binding and signature verification.
2. Nonce one-time consumption under concurrent requests; deterministic quorum/maker-checker.
3. Key rotation/revocation/anti-rollback and exact replay; changed request conflicts.
4. Missing authority fails closed; test keys cannot be mistaken for production.
5. Control validates receipts without reading Governance DB; clean Governance-owned persistence/backup/restore only after D-01 decision.

## WS6 continuation — Governance receipt verifier candidate (2026-11-03)

**Status: IMPLEMENTED / TESTED as a WS6 crate-local DRAFT; NOT RATIFIED; NOT DEPLOYED.** The candidate is isolated in `crates/runalith-trust/src/governance_receipt.rs` and does not alter the shared `runalith-protocol` contract or the current `GovernanceApprovalReceiptV1` shape.

### Draft signature profile

The receipt's existing `authenticator` JSON object is interpreted by the new closed `GovernanceReceiptSignatureEnvelopeV1`:

`schema_version`, `kind=governance_approval_receipt`, `signature_algorithm=Ed25519`, `provider_id`, `scope`, `issuer`, `audience`, `key_id`, `trust_snapshot_ref_sha256`, `trust_root_sha256`, `nonce`, `issued_at`, `expires_at`, `request_sha256`, `subject_sha256`, `evidence_sha256`, `policy_sha256`, `receipt_payload_sha256`, `receipt_payload`, `signature`.

- `receipt_payload` is the exact serialized `GovernanceApprovalReceiptV1` with only `authenticator` removed.
- `receipt_payload_sha256` is SHA-256 over RFC 8785/JCS canonical UTF-8 bytes of that payload.
- `request_sha256` is SHA-256 over the complete canonical typed request, including its authenticator. `subject_sha256` is over the exact canonical `ApprovalSubjectV1` object.
- `trust_snapshot_ref_sha256` is the SHA-256 of the canonical six-field `TrustSnapshotRefV1`; it is distinct from the complete trust configuration fingerprint and does not itself prove high-water observation.
- The Ed25519 signature covers canonical UTF-8 JSON for the entire envelope with only `signature` removed. It therefore binds issuer, audience, key/config references, nonce, timestamps, request/subject/evidence/policy digests and receipt payload.
- `key_id` must equal the key selected by the supplied administrator trust configuration for `trust_root_sha256`. Host-pinned issuer/audience/scope must match the request, service identity and configured domain; none are taken as authority from caller JSON alone.
- `verify_observed_signed_envelope` separately requires the supplied `TrustConfigurationObserver` to confirm explicit high-water observation and checks key validity/revocation at verification time.
- `GovernanceReceiptSigningPort` is a host-owned private-key custody port. `build_governance_receipt_authenticator_v1` assembles the exact envelope, asks the port to sign the canonical preimage, and independently verifies the returned Base64 signature against the selected configured public root before returning it. The crate contains no private-key implementation or credential.

The signer builder also requires explicit trust high-water observation and current key validity. The signing port cannot substitute a different key ID; the configured key ID/root must match and the generated envelope must pass the same Ed25519 envelope validator used by verification.

### Nonce contract draft

`GovernanceReceiptNonceLedger` is a separate port from `EvidenceVerificationNonceLedger` and WS7 checkpoint/source-operation nonces. It atomically binds `(nonce, signed_envelope_sha256, receipt_payload_sha256, request_sha256)`. The required outcomes are `Consumed`, byte-identical `ExactReplay`, `BindingConflict` for any changed binding, and `Unavailable` when durable authority cannot be reached. The crate supplies only process-local mutex and `#[cfg(test)]` SQLite adapters. The SQLite test adapter opens a new connection per operation, uses `BEGIN IMMEDIATE`, and is exercised across 16 concurrent calls plus adapter reconstruction over the same file to simulate restart. It proves the port's atomic/reopen semantics under SQLite in tests only; its `ws6_test_receipt_nonces` table is test-only and does not establish a production schema, persistence owner, migration or deployable adapter.
