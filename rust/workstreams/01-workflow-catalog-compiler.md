# Workstream 1 — Workflow Catalog & Plan Compiler

**Deployable:** Workflow Control. **Status:** Rust compiler, workflow-local policy composition and stable `W1_*` compiler error codes implemented; focused Rust/Node checks pass. Cross-workstream contracts remain DRAFT/BLOCKED; accountable owner remains unassigned. See the [master eight-part plan](../EIGHT_PART_PARALLEL_PLAN.md).

## Mandate

Compile user intent and versioned definitions into a validated, immutable, reproducible workflow plan. This workstream describes *what* the workflow is; it does not run tasks or advance workflow state.

## Ownership

- Built-in/custom roles and workflow definitions, exact versions and catalog validation.
- Role capability and typed input/output contracts; dependency DAG schema and validation.
- Trusted-skill references/pins as compiler inputs (trust decision itself belongs to workstream 6).
- Normalization, compiler validation/error vocabulary, immutable plan snapshots, canonicalization and plan digests.
- Workflow-local policy pack and success-contract schema/composition included in a plan. Global trust, reviewer quorum and approval policy remain workstream 6.

## Explicit non-ownership

No approval decision/signing keys; no workflow instance state, scheduling, claims, leases, retries or recovery; no process/provider execution; no session/artifact storage; no AGG verification; no MCP handlers.

## Current code map

`runalith-domain` workflow/catalog modules; catalog/plan modules currently inside `runalith-store`; Control-facing compiler paths in `runalith-runtime`; Node workflow compiler, role catalog and the Rust Node-oracle scripts/fixtures. `runalith-domain` and `runalith-store` are shared crates: this assignment is module-level, not ownership of the entire crate.

## Public outputs

`WorkflowDefinitionV1`, `RoleDefinitionV1`, `WorkflowDefinitionPinV1`, `RoleDefinitionPinV1`, `SkillPinRefV1`, `WorkflowPolicyDefinitionV1`, `WorkflowPolicySnapshotV1`, `WorkflowPolicyPinV1`, `WorkflowSuccessContractV1`, `WorkflowPolicyCompositionV1`, `CompiledPlanV1`, `PlanDigestV1`, typed task DAG and stable compiler errors. Plans bind exact definition versions, task identities, dependencies, typed I/O contracts and optional policy composition.

The first Rust V1 draft is in `crates/runalith-domain/src/workflow_catalog_v1.rs`. Built-in roles resolve from the immutable domain catalog; custom roles require exact supplied versions. `WorkflowDefinitionPinV1` binds the full workflow definition (including description), and `RoleDefinitionPinV1` binds the full built-in/custom role definition (including custom prompt, capability set, permissions and tools) by exact ID/version and content fingerprint. `SkillPinRefV1` binds `role_id`, `role_version`, `skill_id` and Node-compatible `bundle_sha256`. `CompiledPlanV1` retains the existing Node-compatible inner workflow-plan digest and adds an outer SHA-256 over the canonical plan, workflow/role definition pins and sorted skill pins. A Node-generated canonical-bytes/hash vector is checked in at `crates/runalith-domain/tests/fixtures/node-compiled-plan-v1.json`. The `ReadOnlyTrustedSkillResolver` port accepts only an already-resolved ID/digest pair; a missing result fails closed. This adapter shape is a proposal for Workstream 6 review, not an assertion that Governance has ratified its `TrustedSkillResolutionV1` fields or trust semantics. In particular, the current legacy Store result has `content_sha256` and an exact skill version, while this draft uses Node `bundle_sha256`; equivalence and any authority/receipt binding are unresolved until W6 ratifies the V1 mapping.

Pure policy/success-contract V1 schema and composition now live in `crates/runalith-domain/src/workflow_policy_v1.rs`. It normalizes Node predicate contracts, validates immutable policy snapshots/content hashes, checks semantic conflicts and plan compatibility, sorts exact policy versions, namespaces IDs as `p-{policy_id}-{rule_id}`, and produces `WorkflowPolicyCompositionV1` (base contract, composed contract, snapshots and compact pins). `CompiledPlanV1::with_policy_composition` validates the composition against its exact task DAG and includes it in the outer plan digest; tampering or version/pin drift fails verification. Node-generated parity fixtures cover policy snapshot hash, composition and the full plan envelope. `PolicyPlanContextV1::from(&CompiledWorkflowPlan)` maps catalog role IDs, whereas the legacy Node custom-plan adapter currently presents synthetic child role labels; W2 must define the explicit adapter mapping before using role predicates on legacy custom plans. The typed context also does not infer an executor identity: `execution_exit_code_equals` requires an explicit `ExecutionManager` identity supplied by the caller. This module does not persist or attach policies to live workflow instances, execute predicates, or evaluate durable evidence. W2 still owns lifecycle attachment/evaluation and must confirm how its policy-attachment transition consumes a newly composed immutable plan/revision.

**Consumers:** workstream 2 (workflow creation/admission); workstream 6 (trusted-skill resolution); workstream 7 (read-only plan references). The producer owns semantic fields; workstream 8 owns transport envelope/serialization conventions.
