### Atomic checkpoint nonce/high-water transition

Follow-up hardening replaced the nonce-only callback contract with `commitCheckpointTransition`. After cryptographic, freshness, release-binding and continuity checks pass, the callback receives request nonce, authority ID, candidate/rollback hashes, expected prior high-water sequence and checkpoint digest, and the proposed next sequence/digest. Exact boolean `true` is required; missing configuration, rejection and exceptions fail closed. Legacy `consumeRequestNonce` is retained as an input name for source compatibility but is never invoked and cannot authorize verification. The result separates `cryptographicResponseVerified`, `nonceConsumed` and `checkpointStateAdvanced`; `verified` requires all three predicates and zero blockers. Atomic transition failures are classified as continuity/anti-rollback failures.

The test-local compare-and-swap model binds authority/candidate/rollback identity, nonce uniqueness, expected prior sequence/digest, next sequence and previous-digest continuity. Tests verify exact replay rejection, legacy callback rejection, and two separately signed responses with distinct nonces racing from the same high-water state; only one transition succeeds. These tests establish local regression behavior only, not cross-process or durable-store atomicity. Production still requires a host-owned, independently protected monotonic store and authenticated adapter; ambiguous commit outcomes must be resolved by querying the authoritative transaction result, not by blindly retrying. `productionAuthorityEstablished` remains false.

Candidate inspection, byte alignment, a count of 71, caller-supplied keys, locally signed manifests and self-asserted checkpoint flags cannot clear it. `docs/agg-production-trust-provisioning-runbook.md` records the owner, signed manifest/receipt/source snapshot inputs, disjoint-root provisioning, exact 71-path/archive equality and byte-binding predicate, and closure conditions. A future host-owned adapter must produce the authenticated result before this blocker can be cleared.
