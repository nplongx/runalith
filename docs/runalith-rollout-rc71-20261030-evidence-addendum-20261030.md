### Change and TDD evidence

The effective-host validator previously pinned target and parent `/proc/<pid>/stat` start-time identities and checked the target PPid, but did not re-read the two command lines or PPid after reading the environment. A process could `exec` under the same PID/start time while separate `/proc` files were being inspected. Added target/parent executable link+device+inode pins, command-line and PPid re-reads, both start-time re-reads, and exact target environment-byte re-read. Any observed executable, argv, environment, PID or parent change fails closed with `AGG_TRUST_CONFIG_HOST_PROCESS_IDENTITY_CHANGED`.

Four regression cases simulate target-process `exec`, parent-process `exec`, same-argv environment replacement and same-argv executable replacement between reads; command-line fixtures use actual NUL-delimited `/proc` bytes. TDD red: `node --test tests/test-adaptive-goal-trust-configuration.mjs` failed because the validator returned `PASS` for changed command lines/environment. TDD green: the same command passed 16/16 after the fix. The operator runbook states the exact checks and limitation: separate `/proc` reads are not an atomic process snapshot or pidfd lifetime pin; an exec preserving executable object, argv and environment is observationally equivalent, and no userspace sequence can rule out a change immediately after its final read. The check does not prove host ownership, trust-ledger state or external checkpoint continuity.
