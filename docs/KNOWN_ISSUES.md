## Current RC.11 activation blockers

The published RC.11 package is a test candidate only. Its exact asset identity is listed in the [release notes](release-notes-1.0.9-rc.11.md). A successful offline test suite or a published GitHub pre-release does not satisfy host trust provisioning, external checkpoint authority, or workflow reconciliation.

1. **`PRODUCTION_AGG_TRUST_CONFIGURATION_NOT_VERIFIED`.** The host/security authority must provision `AGG_KNOWLEDGE_VERIFICATION_TRUST_CONFIG_JSON` and `AGG_REVIEW_IDENTITY_TRUST_CONFIG_JSON` through host-owned configuration loading. Independently verify effective runtime values, different provider identities and disjoint Ed25519 public roots, exact scopes, configuration versions, validity windows, and rotation/revocation state. See the [trust provisioning runbook](agg-production-trust-provisioning-runbook.md).
2. **`PRODUCTION_AGG_TRUST_LEDGER_EXTERNAL_ANCHOR_NOT_VERIFIED`.** A host-owned authenticated checkpoint adapter and independently protected monotonic store must verify the signed challenge response, exact candidate/rollback hashes, freshness, sequence and chain continuity. The repository's protocol contract explicitly reports `productionAuthorityEstablished: false`; a caller-supplied `verified` flag or local SQLite history is not proof.
3. **`ACTIVE_EXECUTING_WORKFLOWS_MUST_DRAIN` and `RUNNING_TASKS_MUST_DRAIN`.** The latest read-only reconciliation observed 60 `EXECUTING` jobs and 61 running tasks with zero lease rows. All 61 running tasks lacked persisted execution metadata and had unresolved authoritative owner/provider/runtime identity. Missing lease rows do not prove a worker is dead and do not authorize a retry, reset, terminalization, kill, restart, or redispatch. Follow the [RC.11 recovery guidance](goal-plan-execution-recovery-guidance-rc11-followup.md) and obtain per-record decisions from the responsible owners/providers.

The installed host remains on RC.8 according to the recorded read-only verification; the RC.11 package has not been installed or activated. Do not try to clear the version mismatch by installing the candidate. The current rollout preflight exit code `3` means `BLOCKED`; the installed-version mismatch is expected while RC.8 remains installed and is not activation approval.

## Formal Phase 2 production/frozen-release blockers

The blockers below apply to calling the candidate official/frozen, using it for the formal Phase 2 deployment lane, or claiming production readiness. They do not by themselves veto an experimental pre-release under [the separate minimum standard](RELEASE_POLICY.md). Keep every status accurate; do not forge, silently waive, or report formal blockers as passed.

The historical RC.4 testing package is `324541` bytes (SHA-256 `bfb68c11317dc394f6d1ea85368a801dc9f6f473974e34e96d02736747776552`), built and inventoried from the source commit selected by tag `v1.0.9-rc.4`. Verify the release asset with its `.sha256` sidecar before use. This identity is for the experimental package only; it is not the missing official frozen release artifact and closes none of the production blockers.

1. **Frozen release artifact identity is not established.** The official frozen bundle is not present in the working tree, so the formal process cannot prove that the candidate under review is the authorized frozen artifact. Resolve this through the authorized bundle custodian; do not recreate or overwrite the frozen path as a workaround.
2. **Fresh exact-scope authorization and gate approval are missing.** The formal deployment lane requires a valid, signed, scope-bound record from the designated authorization authority and the correct gate transition by its custodian.
3. **Independent candidate review is missing.** An authorized reviewer must independently review the precise bundle and inventory hashes before a frozen/production release. Self-verification and CI results are not substitutes for this review. The new local RC.5 candidate and post-install file-content comparison are supplemental evidence only; they are not an authorized independent disposition or a verified source-inventory binding. See [issue #3](https://github.com/nplongx/runalith/issues/3).
4. **CASE-06 policy disposition is unresolved.** A valid signed disposition and verification against a trusted public-key anchor are required from the policy/specification authority for the formal release lane.
5. **Fresh Phase 2 host preflight is blocked.** Re-run the preflight in the intended host environment and satisfy its disk/resource requirements before formal Phase 2 deployment.
6. **Static release-policy validation is blocked by prerequisites.** Re-run after frozen identity, review, authorization, and host-preflight prerequisites are satisfied; unrelated unit tests do not close this gate.
7. **Authorization audit reconciliation is outstanding.** The one-shot authorization has been consumed and the audit metadata is stale. The authorized audit/authorization custodian must reconcile the official history before formal production/deployment approval; do not edit official records locally to manufacture a clean result.
8. **Independent `output_commit` attestation is missing.** A task's successful exit, package SHA-256, or local post-install comparison does not independently attest the `output_commit` evidence consumed by a release gate. The independent verifier must bind the relevant immutable input/snapshot and exact result/evidence bytes, fail closed on missing or mismatched evidence, and leave the gate blocked until the authorized proof is verified. Track the work in [issue #19](https://github.com/nplongx/runalith/issues/19).

## Runtime and acceptance gaps

- **Real autonomous specialist execution is not yet proven.** The successful local workflow evidence used scripted/prevalidated host task payloads. It proves workflow persistence and typed-evidence checks under that harness, not the quality or reliability of autonomous model workers.
- **Real OpenClaw/Gateway integration E2E is still required for M12.** Unit/contract tests do not prove native session/run identity, worker placement, cancellation/fencing, teardown, or recovery against a live isolated Gateway.
- **External delivery and exactly-once side effects are unproven.** Do not infer that durable local task completion guarantees a remote message/action was delivered exactly once.
- **Installed bundle identity has a narrower verification boundary.** After the 2026-10-20 reinstall, the local runtime health check returned `ok` and version `1.0.9-rc.5`; the workflow catalog responded. A read-only comparison matched the content hashes for all 62 file entries inside the new timestamped local RC.5 candidate against the installed plugin tree, with no missing files or mismatches. The host still does not expose the exact installed `.mcpb` archive bytes, and the local candidate was built from a dirty working tree without an independent source inventory. This verifies installed file-content parity for that local candidate, not the exact installed archive container, the published GitHub release asset, or any separately frozen/authorized bundle. See the [verification dossier](installation-verification-1.0.9-rc.5-20261020.md).
- **The local plugin is not an OS sandbox.** Workspace boundaries and structured command checks are defense-in-depth, not a replacement for a separately reviewed OS/container sandbox.
- **Legacy host-specific paths remain.** Some root-level compatibility/runtime scripts and older tests still refer to `/home/long/...`; the plugin entrypoint is `server/index.js`, but a broader portability cleanup needs targeted tests and should not be mixed with release-gate changes.

## Exit criteria

For a testing pre-release, satisfy the minimum checklist in [the release policy](RELEASE_POLICY.md), identify the exact tagged source/package, attach a checksum-verified artifact, and disclose these open limitations. Formal production/frozen-release blockers close only when the required authorized records and independent verification exist for the exact candidate identity. Runtime gaps close only with reproducible isolated integration evidence. Keep unavailable, ambiguous, or stale evidence marked blocked/unverified; never reinterpret it as a pass.
